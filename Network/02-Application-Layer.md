# 응용 계층 (Application Layer)

## 개념

애플리케이션 간 데이터를 교환하는 형식과 절차를 정의한다. 프로토콜은 데이터의 종류뿐 아니라 통신 목적, 보안, 실시간성, 상대 시스템의 지원 여부에 따라 선택한다.

## 프로토콜별 비교

| 프로토콜 | 용도 | 전송 방식 | 기본 포트 |
| --- | --- | --- | --- |
| HTTP | 웹 및 API 요청·응답 | TCP (HTTP/1.x, 2) | 80 |
| HTTPS | TLS로 보호하는 HTTP | TCP 또는 QUIC(UDP 기반) | 443 |
| FTP | 파일 전송 | TCP | 21 (제어) |
| FTPS | TLS로 보호하는 FTP | TCP | 21 (명시적 TLS), 990 (암시적 TLS) |
| SFTP | SSH 기반 파일 전송 | TCP | 22 |
| TFTP | 단순 파일 전송 | UDP | 69 (초기 요청) |
| DNS | 도메인에 대응하는 IP 등 조회 | UDP / TCP | 53 |
| DHCPv4 | IP 및 네트워크 설정 자동 할당 | UDP | 67(서버), 68(클라이언트) |
| SSH | 안전한 원격 서버 접속 | TCP | 22 |
| Telnet | 원격 서버 접속 | TCP | 23 |
| SMTP | 메일 전송·제출 | TCP | 25, 587 |
| POP3 | 메일 다운로드 | TCP | 110 |
| IMAP | 메일 조회·동기화 | TCP | 143 |
| SNMP | 네트워크 장비 관리 | 주로 UDP | 161, 162 |
| NTP | 시스템 시간 동기화 | 주로 UDP | 123 |

포트는 기본값이며 변경 가능하다. 포트 번호만으로 응용 프로토콜을 확정할 수 없다. DNS에는 DoH/DoT 같은 별도 전송 방식도 있다.

## 동작 원리 및 선택 기준

- HTTP와 HTTPS: HTTPS는 TLS로 통신을 보호한다(암호화, 무결성, 일반적으로 서버 인증).
- FTP와 SFTP: FTP는 제어 연결과 데이터 연결을 구분한다. SFTP는 FTP에 암호화를 추가한 것이 아니라 SSH 기반의 별도 프로토콜이다.
- DNS와 DHCP: DNS는 상대의 주소를 조회하고, DHCP는 자신의 네트워크 설정을 할당받는다.
- SSH와 Telnet: 둘 다 원격 접속에 사용하지만 기본 Telnet은 평문이며 SSH는 암호화한다.
- SMTP / POP3 / IMAP: SMTP는 발송과 서버 간 전달, POP3는 다운로드, IMAP은 서버와 상태 동기화에 주로 사용한다.

## 실무 예시

| 데이터 | 통신 목적 | 가능한 프로토콜 |
| --- | --- | --- |
| 고객 정보 | 화면에서 실시간 조회 | HTTPS |
| 고객 정보 | CSV 파일로 일괄 전송 | SFTP |
| 고객 정보 | 웹에서 엑셀 다운로드 | HTTPS |
| 배치 결과 알림 | 이메일 발송 | SMTP |

파일 전송이라고 반드시 FTP를 쓰는 것은 아니다. 양쪽이 같은 통신 규격을 지원해야 한다. HTTP 요청을 FTP 서버에 보내면 TCP 연결이 가능하더라도 정상적인 응용 통신은 성립하지 않는다.

```javascript
axios.get("https://example.com/customer?id=100");
```

```cmd
nslookup example.com
```

```bash
# 접속 권한이 있는 실습 서버로 예시 주소를 변경한다.
ssh developer@10.0.0.20
```

## 면접 질문

**Q. 응용 계층 프로토콜을 결정하는 기준은 무엇인가요?**

A. 데이터 형태, 통신 목적, 보안과 성능 요구사항, 상대 시스템의 지원 규격을 고려합니다.

**Q. DNS와 DHCP의 차이는?**

A. DNS는 도메인에 대응하는 IP 주소 등을 조회하고, DHCP는 IP 주소와 게이트웨이 등 네트워크 설정을 자동 할당합니다.
