# 네트워크 접근 계층 (Network Access Layer)

## 개념

인터넷 계층에서 선택한 다음 전달 대상까지 프레임 등을 실제 통신 매체로 전송한다. OSI의 데이터 링크 계층과 물리 계층에 대응한다.

| 기술·프로토콜 | 역할 |
| --- | --- |
| Ethernet (IEEE 802.3) | 주로 유선 LAN의 프레임 전송 |
| Wi-Fi (IEEE 802.11) | 무선 LAN의 프레임 전송 |
| ARP | 로컬 링크에서 IPv4에 대응하는 MAC 주소 조회 |
| PPP | 두 지점 간 데이터 링크 통신 |
| IEEE 802.1Q | Ethernet VLAN 태깅 |

MAC 주소는 일반적인 Ethernet에서 48비트 링크 계층 주소이다. 운영체제에서 변경하거나 임의 주소를 사용할 수도 있다. IPv6에서는 ARP 대신 ICMPv6 기반 NDP를 이용한다.

## 동작 원리

목적지가 다른 네트워크에 있으면 일반적으로 다음 홉인 게이트웨이의 MAC 주소를 확인한다. 목적지가 같은 링크에 있다면 목적지 자체의 MAC 주소를 확인한다.

ARP 캐시에 주소가 없을 때 ARP Request를 브로드캐스트하고 해당 IPv4 주소를 사용하는 장비가 Reply를 보낸다. 결과를 캐시에 저장한 뒤 프레임을 전송한다.

```mermaid
flowchart LR
    A[PC MAC A] -->|A → B| B[라우터 1 MAC B/C]
    B -->|C → D| C[라우터 2 MAC D/E]
    C -->|E → F| D[WAS MAC F]
```

| 구간 | 출발지 MAC | 목적지 MAC | 목적지 IP |
| --- | --- | --- | --- |
| PC → 라우터 1 | A | B | 10.0.0.20 |
| 라우터 1 → 라우터 2 | C | D | 10.0.0.20 |
| 라우터 2 → WAS | E | F | 10.0.0.20 |

NAT가 없는 Ethernet 기반 라우팅 예시다. IP 주소는 유지되지만 각 라우터에서 새로운 링크 계층 프레임이 만들어진다. L2 스위치는 일반적인 프레임 전달 시 출발지·목적지 MAC을 바꾸지 않는다.

## Ethernet 프레임

```text
[목적지 MAC][출발지 MAC][EtherType][IP 패킷 및 필요 시 패딩][FCS]
```

FCS는 전송 오류를 검출하는 값이다. 손상된 Ethernet 프레임은 일반적으로 폐기된다.

| 장비 | 역할 |
| --- | --- |
| 허브 | 물리 계층에서 신호 전달 |
| L2 스위치 | MAC 주소 테이블로 프레임 전달 |
| 라우터 / L3 스위치 | IP 기준 네트워크 간 패킷 전달 |
| AP | 무선 기기를 네트워크에 연결 |
| NIC | 네트워크 인터페이스 |

## 실습 예시

가정집 PC를 랜선으로 공유기에 연결하면 Ethernet, 무선으로 연결하면 Wi-Fi를 사용한다. 상위 TCP/IP 프로토콜은 동일하게 사용할 수 있다.

```cmd
ipconfig /all
arp -a
getmac
```

위 명령으로 자신의 IP, 물리적 주소, 게이트웨이, ARP 캐시를 확인한다. Ethernet은 인터넷 자체가 아니라 링크 통신 기술이다.

## 면접 질문

**Q. IP와 MAC 주소의 차이는?**

A. IP는 최종 목적지까지 패킷을 전달하기 위한 논리적 주소이고, MAC은 Ethernet 등 로컬 링크에서 프레임을 전달하기 위한 주소입니다.

**Q. 다른 네트워크의 서버 MAC 주소를 직접 ARP로 조회하나요?**

A. 일반적으로 아닙니다. 다음 홉인 게이트웨이의 MAC 주소를 조회합니다.
