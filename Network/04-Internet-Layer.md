# 인터넷 계층 (Internet Layer)

## 개념

IP 주소를 기반으로 최종 목적지를 식별하고 패킷을 전달한다. 라우팅 테이블을 참고해 다음 전달 대상과 인터페이스를 결정한다. OSI의 네트워크 계층에 대략 대응한다.

| 프로토콜 | 역할 |
| --- | --- |
| IPv4 | 32비트 IP 주소 기반 패킷 전달 |
| IPv6 | 128비트 IP 주소 기반 패킷 전달 |
| ICMP | 네트워크 오류 보고 및 진단 |
| IPsec | IP 패킷의 인증·무결성 및 암호화 등 |
| IGMP | IPv4 멀티캐스트 그룹 관리 |

IP는 비연결형이며 최선형(best effort) 전달을 제공한다. 패킷의 도착이나 순서, 재전송을 자체적으로 보장하지 않는다.

## 동작 원리

- 라우팅: 경로 정보를 결정·관리한다.
- 포워딩: 라우팅 정보에 따라 실제 패킷을 다음 대상으로 넘긴다.
- 라우팅 테이블에 일치하는 경로가 여러 개라면 일반적으로 가장 긴 프리픽스(가장 구체적인 경로)를 우선한다.

| 목적지 네트워크 | 다음 전달 대상 (예시) |
| --- | --- |
| 192.168.0.0/24 | 직접 연결 |
| 10.0.0.0/24 | 라우터 A |
| 0.0.0.0/0 | 기본 게이트웨이 |

목적지 IP가 10.0.0.20이라면 위 예시에서는 라우터 A 방향으로 전달한다. 각 라우터는 자신의 테이블을 참고하므로 송신 PC가 최종 목적지까지의 모든 경로를 알아야 하는 것은 아니다.

## IPv4 / IPv6

| 구분 | IPv4 | IPv6 |
| --- | --- | --- |
| 주소 크기 | 32비트 | 128비트 |
| 주소 예시 | 192.168.0.10 | 2001:db8::1 |
| 기본 헤더 | 20 Byte | 40 Byte |
| 브로드캐스트 | 지원 | 미지원(멀티캐스트 등 사용) |

## 실습 예시

```cmd
route print
ping 10.0.0.20
```

```bash
ip route
```

`ping`은 ICMP Echo Request / Reply를 사용하고 TCP나 UDP 포트를 사용하지 않는다. ping 성공은 HTTP 서비스가 정상이라는 뜻이 아니다. 반대로 ICMP 차단 환경에서도 TCP 통신은 가능할 수 있다. 예시 IP는 실제 접근 권한이 있는 환경의 주소로 변경한다.

## 면접 질문

**Q. IP는 데이터 전송의 신뢰성을 보장하나요?**

A. 아닙니다. IP는 최선형 패킷 전달을 제공하며 신뢰성은 TCP 등 상위 프로토콜에서 제공할 수 있습니다.

**Q. 인터넷 계층과 전송 계층의 차이는?**

A. 인터넷 계층은 IP 기반 목적지까지 패킷 전달을 담당하고, 전송 계층은 포트로 서비스를 식별하고 프로세스 간 전송을 담당합니다.
